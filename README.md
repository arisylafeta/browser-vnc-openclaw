# EasyClaw Browser-VNC Template

A complete OpenClaw deployment with dedicated VNC-enabled browser access.

## Overview

This template provides:
- **OpenClaw Gateway** - AI agent orchestration with browser automation
- **Browser-VNC Service** - Chromium with VNC and web-based access
- **Hard Isolation** - Complete separation per deployment
- **Persistent Data** - Browser cookies, logins, and downloads survive restarts
- **VNC Password Protection** - Secure access to browser (not in official image)

## Architecture

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   OpenClaw  │────▶│ Docker Proxy│────▶│  Docker API │
│   Gateway   │     │  (security) │     │             │
└──────┬──────┘     └─────────────┘     └─────────────┘
       │
       │ CDP (internal Docker network)
       ▼
┌─────────────┐
│ Browser-VNC │
│  - Chromium │
│  - Xvfb     │
│  - x11vnc   │
│  - noVNC    │
└──────┬──────┘
       │
       │ Port 6080
       ▼
   [User Browser]
```

## Differences from Official openclaw-sandbox-browser

This template uses a **custom browser image** based on the official OpenClaw sandbox browser, with one key modification:

**Official Image:** Runs `x11vnc` with `-nopw` (no password)
**This Image:** Supports `VNC_PASSWORD` environment variable for secure access

## Access Information

After deployment, you'll receive:

- **OpenClaw Gateway**: `http://<server-ip>:18789?token=<gateway-token>`
- **noVNC URL**: `http://<server-ip>:6080/vnc.html`
- **VNC Password**: As configured in `VNC_PASSWORD`
- **CDP Endpoint**: `http://browser-vnc:9222` (internal, for OpenClaw)

## Services

### OpenClaw Gateway (Port 18789)
The main AI agent gateway. Configure AI provider API keys in `.env`.

### Browser-VNC (Port 6080)
Chromium browser accessible via:
- **Web Browser**: noVNC at `http://<ip>:6080/vnc.html`
- **VNC Client**: Connect to `<ip>:5900` (if exposed)
- **OpenClaw Control**: Via CDP on internal port 9222

Key features:
- VNC password protection (configurable via `VNC_PASSWORD`)
- 1920x1080 display resolution
- Persistent profile (cookies, extensions, settings)
- Downloads folder persistence

### Docker Proxy
Secure Docker socket proxy for OpenClaw's sandboxing capabilities.

## Environment Variables

See `.env.example` for all configuration options.

### Required
- `OPENCLAW_GATEWAY_TOKEN` - Secure token for gateway authentication
- `VNC_PASSWORD` - Password for VNC access (auto-generated by EasyClaw)
- At least one AI API key (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, etc.)

### Optional
- `TELEGRAM_BOT_TOKEN` - Telegram bot integration
- `GITHUB_TOKEN` - GitHub integration
- `CF_TUNNEL_TOKEN` - Cloudflare tunnel for public access

## Persistence

Data is persisted across container restarts:

- **openclaw-data**: OpenClaw configuration and state
- **openclaw-workspace**: User projects and files
- **browser-data**: Chromium profile (cookies, extensions, settings)
- **browser-downloads**: Browser downloads folder
- **browser-cache**: Browser cache and temporary files

## OpenClaw Configuration

The bootstrap script automatically configures OpenClaw with browser support:

```json
{
  "browser": {
    "enabled": true,
    "attachOnly": true,
    "cdpUrl": "http://browser-vnc:9222",
    "noSandbox": true,
    "headless": false
  }
}
```

This tells OpenClaw to:
- Connect to the browser-vnc container via CDP
- Not launch its own browser instance
- Use non-headless mode (visible browser)

## Security

This template implements defense-in-depth security based on OpenClaw's sandbox hardening best practices:

### Container Hardening (browser-vnc)
- **Capability Dropping**: All Linux capabilities dropped (`cap_drop: ALL`)
- **No New Privileges**: Prevents privilege escalation (`no-new-privileges:true`)
- **Read-Only Root**: Filesystem is read-only except for tmpfs and volumes
- **Tmpfs Mounts**: Writable directories (`/tmp`, `/var/tmp`, `/run`) mounted as memory-only
- **Non-Root User**: Runs as `sandbox` user (not root)

### Network Security
- **CDP Internal-Only**: Chrome DevTools Protocol is NOT exposed externally
  - CDP has NO authentication and allows arbitrary code execution
  - Only accessible within Docker network (OpenClaw → browser-vnc)
- **VNC Password Protection**: Configurable via `VNC_PASSWORD` environment variable
- **Docker Proxy**: Restricts Docker API access for OpenClaw sandboxing
- **Hard Isolation**: Each deployment is completely isolated

### Port Exposure
| Port | Service | External Access | Notes |
|------|---------|-----------------|-------|
| 18789 | OpenClaw Gateway | ✅ Yes | Requires token authentication |
| 6080 | noVNC Web | ✅ Yes | Web-based VNC access |
| 5900 | VNC Server | ✅ Yes | Direct VNC client access |
| 9222 | Chrome CDP | ❌ No | **Internal Docker network only** |

## Testing Locally

1. Copy environment file:
   ```bash
   cp .env.example .env
   # Edit .env and add your values
   ```

2. Build and start:
   ```bash
   docker-compose build
   docker-compose up -d
   ```

3. Check status:
   ```bash
   docker-compose ps
   docker-compose logs -f openclaw
   docker-compose logs -f browser-vnc
   ```

4. Access services:
   - OpenClaw: http://localhost:18789
   - noVNC: http://localhost:6080/vnc.html

## Troubleshooting

### Can't connect to noVNC
1. Check container is running: `docker-compose ps`
2. Check logs: `docker-compose logs browser-vnc`
3. Verify VNC password is set correctly

### OpenClaw can't control browser
The new architecture uses Docker DNS and direct Chrome binding:
1. Verify both services are on same Docker network (automatic with docker-compose)
2. Check OpenClaw logs: `docker-compose logs openclaw | grep -i browser`
3. Verify Chrome is listening: `docker-compose exec browser-vnc ss -tlnp | grep 9222`
4. Test from OpenClaw container: `docker-compose exec openclaw curl http://browser-vnc:9222/json/version`

### Browser data not persisting
1. Check volume mounts: `docker volume ls`
2. Verify write permissions in container
3. Restart services: `docker-compose restart`

## Port Allocation

**Note:** This template does NOT use `ports:` in docker-compose.yaml. Port exposure is handled by:

1. **Coolify API**: Backend passes `portsMappings` to Coolify
2. **Service Discovery**: Coolify injects `${SERVICE_FQDN_*}` variables
3. **Internal Networking**: Services communicate via Docker network

Port mapping format: `external:internal`
- `18789:18789` - OpenClaw gateway
- `6080:6080` - noVNC web interface  
- `5900:5900` - VNC server
- ~~9222~~ - Chrome CDP (internal Docker network only, not exposed)
